# Компактный редизайн TranscribeWindow

## Problem

Текущее главное окно `TranscribeWindow` (240×184 px, системный заголовок, кнопка 112×56 + шестерёнка 56×56, языковая полоска, строка статуса) занимает слишком много места на экране и загораживает приложения, поверх которых пользователь диктует текст. Системный заголовок добавляет визуальный шум и лишнюю высоту, а перетаскивать окно можно только за него.

Цель: превратить окно в минимальный плавающий виджет — без заголовка, перетаскиваемый за любую точку фона, с плотной компоновкой и уменьшенными элементами — сохранив всю текущую функциональность.

## Требования

### Функциональные

**FR-1. Окно без системного заголовка.**
- `SystemDecorations="None"` — нет заголовка, рамки и системных кнопок (свернуть/развернуть/закрыть).
- Собственные скруглённые углы (радиус 12–16 px) и тень; на Windows — прозрачный фон окна (`TransparencyLevelHint`) + `Border` с фоном темы, чтобы углы были действительно скруглены.
- `Title` остаётся заданным (для Alt-Tab и панели задач).

**FR-2. Перетаскивание за грип-полоску (как в Windows Voice Typing).**
- Наверху окна — узкая заголовочная зона (~18 px) с центрированной серой полоской-грипом (~40×4 px, скруглённая), как в стандартном приложении голосового ввода Windows (Win+H).
- Перетаскивание начинается **только** нажатием левой кнопки мыши в этой заголовочной зоне (`Window.BeginMoveDrag(PointerPressedEventArgs)` в её обработчике `PointerPressed`). Остальная площадь окна окно **не** перетаскивает.
- Курсор над грип-зоной — «рука»/«перемещение»; при наведении полоска слегка темнеет.

**FR-3. Минимизация размера окна.**
- Целевая площадь — не более ~50 % текущей (текущая: 240×184 ≈ 44 200 px²). Ориентиры по вариантам: 260×56 (лента), 64×64 в свёрнутом виде (док), 168×96 (мини-карточка).
- `CanResize="False"`, `Topmost="True"` — сохраняются.
- Размер задаётся `SizeToContent` либо фиксированно — по выбранному варианту дизайна.

**FR-4. Сохранение позиции окна.**
- Так как заголовка нет и окно позиционируется пользователем вручную, его позиция сохраняется в настройках (`JsonSettingsService`, новые ключи, например `TranscribeWindowPosX` / `TranscribeWindowPosY`) при завершении перетаскивания или закрытии.
- При старте позиция восстанавливается; если сохранённая точка вне видимой области экранов (отключённый монитор, смена разрешения) — окно возвращается в позицию по умолчанию (`CenterScreen`).

**FR-5. Функциональность сохраняется полностью.**
- Кнопка записи с `WaveformView` и состояниями: idle / recording (синий фон) / loading (спиннер на синем фоне).
- Кнопка настроек (открытие окна настроек).
- Языковая полоска «source · коннектор · target» с состояниями коннектора (on/off/locked) и флайаутом выбора языка (открывается вверх, как сейчас).
- Текст статуса («Ready», прогресс загрузки модели и т. п.) показывается **только** в tooltip при наведении на окно. Постоянно видимой строки статуса и точки-индикатора нет.

**FR-6. Закрытие и управление окном без заголовка.**
- В правом углу грип-зоны — маленькая кнопка «✕» (как в Windows Voice Typing), которая скрывает окно (не завершая приложение и не прерывая настроенный hotkey-workflow).
- Закрытие/скрытие окна остаётся доступным через иконку в трее (текущий механизм tray-приложения).
- Дополнительно: `Esc` скрывает окно, когда оно в фокусе (не прерывая запись).
- Окно не показывает системных кнопок управления; сворачивание не требуется.

### Нефункциональные

- **NFR-1.** Поддержка светлой и тёмной темы (динамические ресурсы темы, как в остальном приложении).
- **NFR-2.** Корректная работа при DPI ≠ 100 % (логические пиксели Avalonia, без битмап-хаков).
- **NFR-3.** Все существующие headless-тесты `Parlotype.Desktop.Tests` (включая `TranscribeWindowScreenshotTests`) обновлены под новую разметку; добавлены тесты на восстановление позиции и на то, что drag инициируется только из грип-зоны.
- **NFR-4.** Никаких новых зависимостей; только средства Avalonia 12.
- **NFR-5.** Интерактивные элементы сохраняют минимальную кликабельную зону ≥ 24×24 px, у иконок без подписи есть `ToolTip`.

### Технические заметки (Avalonia)

- Drag: обработчик `PointerPressed` на элементе грип-зоны (например, `Border` в верхней строке `Grid`); в нём вызывается `BeginMoveDrag(e)`. Кнопка «✕» лежит внутри грип-зоны — она помечает событие обработанным, поэтому клик по ней drag не запускает (дополнительно можно проверить `e.Source`).
- Прозрачность: `TransparencyLevelHint="Transparent"`, `Background="Transparent"` на окне; видимая поверхность — корневой `Border` с `CornerRadius`, `BoxShadow` и фоном из ресурсов темы.
- Позиция: `Window.Position` (физические пиксели) сохранять/восстанавливать с учётом `Screens` для валидации видимости.
- Триггеры Definition of Done: изменение затрагивает подсистему настроек (новые ключи) → потребуется ADR; обновить `memory/services/parlotype-desktop.md`.

## Варианты дизайна

**Выбран вариант C2** — мини-карточка с грип-полоской (итерация варианта C по фидбеку: drag-anywhere заменён на грип-зону в стиле Windows Voice Typing, точка-индикатор статуса убрана — статус только в tooltip).
