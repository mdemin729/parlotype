# Localization Skill

Parlotype's interface is on its way to **25 languages**, matching the speech languages
Parakeet supports ([ADR-064](../../../docs/decisions/064-ui-localization-foundation.md),
ADR-069). **Any change to user-facing text must land in every language in the same
change.** A locale left behind is not a follow-up task — it is a broken build.

`SupportedUiLanguages.All` is the current set. Read it; never assume it, and never
hardcode a language list anywhere else.

## The rule

> Adding, changing or removing UI copy means editing `Strings.resx` **and every**
> `Strings.<culture>.resx`, then regenerating `Strings.cs`.

`pwsh scripts/check-localization.ps1` enforces it, `LocalizationParityTests` enforces it in
CI, and a `Stop` hook blocks a session that ends with it broken.

A **typo'd key is silent** — `{loc:Tr Setings_Theme_Title}` compiles, does not throw, and
renders the raw key name in the window. The check catches it; nothing else does.

## Nobody hand-edits a satellite resx

At two languages that was a chore. At twenty-four it is not something a person or an agent
does: each file is ~80 KB of XML with escaping rules and `xml:space="preserve"` on every
node, and an agent asked to emit that fails in ways the parity checks describe badly. Two
scripts bracket the translation instead:

```
Strings.resx ──export-translation-brief.ps1──▶ <culture>.brief.json
                                                      │
                                              (translator works)
                                                      ▼
Strings.<culture>.resx ◀──import-translations.ps1── <culture>.json
```

The brief carries, per key: the English value, your `<comment>`, and the placeholder
indices. The translator returns a flat `{"key": "translation"}` map and nothing else. The
importer owns every byte of XML and **refuses to write** on a missing or orphan key, a
placeholder set that does not match, a named-token mismatch, an empty value, or a value
over 25 characters left verbatim in English.

## Adding a string

1. **Add the key to `src/Parlotype.Desktop/Resources/Strings.resx`** (the neutral file — it
   *is* English; there is no `Strings.en.resx` and there must never be one). Add a
   `<comment>` whenever a translator would otherwise have to guess what a placeholder
   holds or how little room the string has.
2. **Regenerate the accessor:** `pwsh scripts/gen-strings.ps1`. Never hand-edit
   `Strings.cs` — it carries an `<auto-generated>` header and is overwritten.
3. **Use it:**
   - In AXAML: `Text="{loc:Tr Settings_Theme_Title}"` with
     `xmlns:loc="using:Parlotype.Desktop.Markup"`. Never a bare literal.
   - In a view model: `Strings.Settings_Theme_Title`.
4. **Translate it into every language.** Per culture in `SupportedUiLanguages.Translated`:

   ```bash
   pwsh scripts/export-translation-brief.ps1 -Culture de -Missing -Out $SCRATCH/de.brief.json
   # translate the handful of keys it lists
   pwsh scripts/import-translations.ps1 -Culture de -In $SCRATCH/de.json -Merge
   ```

   `-Missing` emits only the keys that locale lacks and `-Merge` applies only what you hand
   it, so a one-string change is one small brief per language rather than a full pass.

   **Read `plans/2026-09-17-twenty-five-ui-languages/glossary-<culture>.md` first.** It
   records the term, register, formality and typography that language already committed
   to. A new string that contradicts its own file is worse than a clumsy one.
5. **Verify:** `pwsh scripts/check-localization.ps1`.

> `git status` may show `Strings.cs` modified while `git diff` is empty — `gen-strings.ps1`
> writes LF into a CRLF tree. `git diff --exit-code` is the real answer. The regenerated
> accessor is byte-identical unless keys actually changed, and it must never change when
> you only add a *language*.

## Key naming

`Area_Component_Purpose`, flat, no nesting:

```
Settings_Theme_Title            Onboarding_Recording_Body
Settings_Theme_Description      Transcribe_Status_Recording
Help_HotkeysHeading             Settings_InterfaceLanguage_SystemDetailFormat
```

Match the area prefix already used by neighbouring keys rather than inventing a new one.

## Composite formats — the part that bites

**Numbered placeholders only. Never interpolate a translated string.**

```csharp
// Wrong — the sentence cannot be reordered, and no translator ever sees it.
StatusText = $"Downloading {modelName}…";

// Right — the generator emits a typed helper for any key containing {0}.
StatusText = Strings.Format_Model_DownloadingFormat(modelName);
```

`gen-strings.ps1` produces `Format_<key>(...)` with one parameter per placeholder, so the
wrong argument count is a compile error rather than a `FormatException` in front of a user.

Add a `<comment>` to any key with placeholders saying what each one holds. A translator
seeing `{0} isn't a source in {1}` with no context will guess, and guess wrong.

### The placeholder a language cannot inflect

A `{0}` is substituted at runtime with a raw value — a model name, a language name, a path
— that arrives with no ending and cannot take one. English does not mark case, so the
problem is invisible from here; Polish, Ukrainian and Finnish mark it everywhere.

Shape the format so the slot needs no grammatical case: put it after a colon, at the start
of a clause, or at the sentence edge. **Rephrase the English rather than handing the
problem downstream** — it is a copy decision, and it is cheapest while the English is still
in front of you.

How strong this signal is: translating into `fr`, `uk`, `pl` and `fi` — four languages from
four different families, working independently and never seeing each other's output — every
one flagged the *same* three keys and every one escaped them the same way, by moving the
slot behind a colon:

| key | English | what they had to do |
|---|---|---|
| `Language_Summary_Format` | `You speak {0} → Parlotype types {1}.` | `Puhut: {0} → …kirjoittaa: {1}.` |
| `Language_ToggleSwitch_TranslateToFormat` | `Translate to {0}` | `Käännä: {0}` |
| `Language_Toast_TargetUnsupportedFormat` | …`in {1}` | `… Käännöskieli: {2}.` |

Four translators converging is the English being wrong, not four translators being fussy.
**When two or more independent languages flag the same key, treat it as a bug in the
neutral file** and raise it with the maintainer instead of letting each language invent its
own workaround.

One technique worth stealing, from Finnish: where a language builds compounds, the
uninflectable value can become a hyphen-prefix on a *native* noun that carries the case
itself — `{0}-ajoympäristöä`, `{1}-moottorissa`. Only the native half inflects, and the
English needs no change. Slavic languages cannot do this; Finnish resolved four keys with
it.

## Never split a sentence across markup

A `TextBlock` built from several `<Run>`s with bound values between them cannot be
translated — the word order is frozen by the markup:

```xml
<!-- Wrong: five Runs around two bound names. No translator can reorder this. -->
<TextBlock>
  <Run Text="This session is already running the" />
  <Run Text="{Binding LoadedRuntimeName}" FontWeight="SemiBold" />
  <Run Text="runtime. Restart to switch to" />
  <Run Text="{Binding SelectedRuntime}" FontWeight="SemiBold" />
</TextBlock>

<!-- Right: one composite format on a view-model property. -->
<TextBlock Text="{Binding RestartRequiredNote}" />
```

The cost is per-run formatting (bold on the substituted values). Pay it — a sentence
that only works in English is worse than one without bold. If the emphasis is truly
load-bearing, restructure the copy so the emphasised part is its own label.

## Keyboard key names stay; the words around them do not

"Ctrl", "Alt", "Shift", "Win", "Space" are printed on the user's keyboard and Windows
leaves them alone in every language. Only the prose around them is translated — and it
must be a **format**, never a concatenation, because languages disagree about where the
words go:

| | side + key | verb + key |
|---|---|---|
| English | `Right Ctrl` | `Hold Right Ctrl` |
| Russian | `правого Ctrl` (genitive) | `Удержание правого Ctrl` |
| Spanish | `Ctrl derecho` (**after**) | `Mantener Ctrl derecho` |

`HotkeyText` (Desktop) does this. Core's `HotkeyGesture.DisplayString` is deliberately
*not* localized: the hotkey log lines write it, and a log that changes language with the
UI cannot be grepped.

## When Core needs to say something

Core has no resources and must never get any. When a sentence has to be built from
something only Core knows — which reserved shortcut a hotkey collided with, why a URL was
refused, what a provider returned — **send the reason as data and choose the words in
Desktop** (ADR-064 amendment):

```csharp
// Core: an identity plus the payload the sentence needs.
public enum ReservedShortcut { LockWorkstation, FileExplorer, /* ... */ }
public readonly record struct HotkeyConflict(
    HotkeyConflictSeverity Severity, string? Description,
    HotkeyConflictReason Reason, ReservedShortcut? Reserved, ActivationMode? ConflictingMode);

// Desktop: the words.
public static string? Conflict(DictationHotkey candidate, HotkeyConflict conflict) => ...
```

Keep the English sentence in Core as the **invariant** form and let the logs write it —
same split as `HotkeyGesture.DisplayString`. Nothing user-facing should read it.

Two things to get right:

- **Shape the format so the substituted noun needs no grammatical case.** Put the slot at
  the start followed by a colon or a verb (`"{0}: no API key configured."`). Russian
  cannot inflect a name it is handed verbatim, and a mid-sentence slot forces it to.
- **Add a test that loops the enum.** Parity checks cannot catch a member added without
  its key: it is missing from *every* language at once, so the languages still agree.
  `LocalizationTests.EveryReservedShortcut_IsTranslated` asserts the Russian rendering
  contains Cyrillic, which fails both for an absent key and for a fallback to English.

Text that arrives from outside — a cloud provider's error message, a file name — is
substituted, never translated. It is someone else's wording.

## What is NOT localized

Leave these in English — they are developer- or protocol-facing, or they are identifiers:

- log messages and exception messages
- engine, model and runtime names: `Whisper`, `Parakeet TDT v3`, `Vulkan`, `gpt-4o-mini-transcribe`
- file names and paths: `settings.json`, `%LOCALAPPDATA%`
- benchmark CLI output (Spectre.Console tables)
- **speech** source/target language names — those come from ICU via `CultureInfo`, not
  from resx. Around 99 names times N locales is not a translation task we own.
- language rows in the interface-language picker: they are **endonyms** ("Русский"), so
  someone stranded in a language they cannot read can still find their own.
- **named tokens inside braces**: `Settings_Prompts_Help_BuiltInBody` documents
  `{speech_lang}` and `{text_lang}`, which the Gemma prompt engine substitutes *by name*.
  Translate a word inside those braces and prompt substitution breaks silently — it is not
  a numbered placeholder and not a wholly untranslated string, so for a while nothing
  looked at it. `import-translations.ps1` now rejects a named-token mismatch outright.

### Some strings are legitimately identical to English

`Updates` is the correct German **and** Dutch for Updates; `Audio`, `Model`, `OK`, `Auto`,
`Help` and `Prompts` come out unchanged in several languages. `NoKeyIsAccidentallyUntranslated`
only fires above 25 characters precisely so these do not drown it in false alarms — which
also means **it cannot catch a genuinely skipped short string.** Nothing can, automatically.
That gap is one of the reasons the per-language glossaries and native-speaker review exist,
and it is worth saying plainly when someone reports a short string "not translated".

Whether a *borrowable* word is translated is the language's call, not a global rule. The
`Cloud` badge is `Облако` / `Nube` / `Chmura` / `Хмара` / `Nuvem` / `Sky` / `Moln` where the
language has a natural short word, and stays `Cloud` in `de`, `fr`, `it`, `nl` where the
loanword is what people actually say. Follow the precedent already in the shipped files
rather than imposing consistency across languages.

## Live switching — the mistake this codebase keeps making

Text bound through `{loc:Tr}` or `Localizer.Entry` re-reads itself when the language
changes. **Copy composed in C# does not.** It is a snapshot: nothing fails, nothing throws,
the page simply keeps the language the app started in — for the life of the process — and
only a human switching languages and looking at that exact page ever notices.

This has now been found three separate times, and the last time it was **six of nineteen
settings sections at once**, two of them reported by a user rather than caught by us. Treat
this section as a hard rule, not advice.

```csharp
protected override void OnCultureChanged()
{
    base.OnCultureChanged();          // re-raises Title
    foreach (var item in Options)
        item.RefreshDisplayName();
}
```

**A structural test enforces it.** `EverySettingsSection_ThatComposesCopyInCSharp_RefreshesItOnCultureChange`
fails the build if a settings view model touches `Strings.` beyond its own `Title` without
overriding the hook. To opt out, add the class to the test's `exempt` dictionary **with a
stated reason** — see below for the one legitimate case.

### Retain the input, not the finished string

The hook can only re-render what the view model can still derive. Three pages needed real
surgery because they had thrown the inputs away:

```csharp
// Wrong — the label is all that survives, and it is already in the old language.
StatusText = Strings.Settings_LlamaCpp_Status_Connected;

// Right — keep what produced it; the text is a function of retained state.
private ServerStatusLabel _statusLabel;
private void SetStatus(ServerStatusLabel label)
{
    _statusLabel = label;
    StatusText = Describe(label);
}
```

Same shape for a measured byte count (`Describe(_lastMeasuredBytes)`) and an OS state
(`DescribeState()` over a retained `_lastEffective`). **Re-rendering must not have side
effects** — a language switch is not a reason to probe a server, walk the models directory
or re-read the registry.

### Plain computed getters do not notify either

`public string IntroText => Strings.Help_Intro;` answers correctly whenever something
re-reads it — but nothing tells a bound control to. It looks right after navigating away
and back, which is exactly how it survives review. Raise it explicitly:

```csharp
OnPropertyChanged(nameof(IntroText));
```

An `ObservableCollection<string>` filled once is worse: re-reading the binding hands back
the same collection holding the same stale strings, so navigation does not even mask it.
Rebuild the collection in the hook.

### Prefer narrowing inside the hook over exempting a class

The exemption list is empty, and it should stay that way.

`PromptSettingsViewModel` used to be in it, for a good reason: its only `Strings` use named
a *copied prompt* — `"{0} (copy)"` — which is written to settings and becomes the user's own
data, and re-translating it would rename something they own. Correct rule, wrong mechanism.
The exemption silenced the **class**, and it turned out to be covering a second use nobody
had noticed: the built-in prompt's display name, hardcoded English in Platform and reaching
the screen untranslated in all 24 languages.

The view model now overrides the hook and refreshes only the built-in row:

```csharp
protected override void OnCultureChanged()
{
    base.OnCultureChanged();
    foreach (var prompt in Prompts)
        prompt.RefreshDisplayName();   // no-ops for anything the user named
}
```

The user-data rule lives as a comment where the code makes the distinction. **An exemption
is a claim about every string in a class, present and future.** If you add one, you are
betting that nobody will add UI copy to that file.

### Copy that lives outside Desktop reaches the screen too

`JsonPromptTemplateRegistry` (Platform) holds `Name: "Default (verbatim transcription)"`.
That literal is *correct* — Platform has no resources — but it was displayed verbatim in
every language, and **no check could see it**: not in AXAML, so the hardcoded-literal scan
missed it; not in resx, so parity missed it.

Same split as everywhere else in ADR-064: **Platform supplies the identity, Desktop chooses
the words.** When you add something to Core or Platform that carries a user-visible name or
sentence, ask whether Desktop should be wording it. The invariant English stays for logs.

This one was found by rendering a page under Hungarian and reading it — which is the only
method that finds this class of bug.

### Surfaces outside the settings pages

The structural test only scans `ViewModels/Settings`. These need the same care and have no
automated guard:

- the tray menu — `NativeMenu` is built once from `App.axaml` and never rebuilt, so
  `AppViewModel` re-raises its label properties
- the record-button tooltip — pushed, not bound, so `HotkeyCoordinator` subscribes to
  `Localizer.CultureChanged` itself and recomputes
- `SettingsWindowViewModel`'s navigation list — nav rows are snapshots of `Section.Title`

## Translation quality bar

- Hold the English register: terse, sentence case, no exclamation marks.
- **The interface is small.** A compact always-on-top widget and a settings window. A
  translation twice the length of the English is a bug, not a style. Keys ending `_Title`,
  `_Button` and `_Tooltip` are the tight ones; `_Body` has room.
- Keep one term per concept across the whole file, and take it from that language's
  `glossary-<culture>.md` in `plans/2026-09-17-twenty-five-ui-languages/`. Extend the
  glossary rather than improvising a synonym.
- Never translate an identifier the user sees verbatim elsewhere (`Parakeet TDT v3`,
  `Vulkan`, `settings.json`, `Esc`). **Declension is not translation.** Finnish and
  Hungarian cannot leave a name bare where grammar demands an ending, and `Parlotypessa`
  or `Visual Studióban` is correct in a way that `Parlotype-ssa` would not be. The rule is
  that the **stem survives and stays recognizable**; the suffix is the language's business.
  Worth a check when a language lands:

  ```python
  # for each protected term, every key that has it in English must still have it
  [k for k in keys_with_term_in_english if term not in translated[k]]
  ```

  Across eighteen languages that came back empty for every term except `Visual Studio`,
  which Czech and Hungarian decline — accepted deliberately.
- Use the locale's own typography: `«…»` in Russian, `„…"` in Polish, `”…”` in Swedish and
  Finnish, `»…«` in Danish, guillemets with narrow no-break spaces in French, a
  non-breaking space before units (`{1} с`).
- **Prefer what that language's Windows says** for the same action over a literal rendering
  of the English — but not blindly. Italian rejected Windows' own *tasto di scelta rapida*
  for "hotkey" because it ran 3.1× the English on a button, and Swedish rejected the native
  *körtid* for "runtime" because it also means duration and would collide with *Väntetid*
  on the neighbouring page. Both recorded the reasoning in their glossary; do the same.
- If you genuinely cannot translate a string, say so in your summary. Do not paste the
  English in as a placeholder — `NoKeyIsAccidentallyUntranslated` will fail, and correctly.

## Adding a new language

```bash
pwsh scripts/export-translation-brief.ps1 -Culture de -Out $SCRATCH/de.brief.json
# one translator does all 389 keys and writes glossary-de.md first
pwsh scripts/import-translations.ps1 -Culture de -In $SCRATCH/de.json
```

Then add the row to `SupportedUiLanguages.All` — `new("de", "Deutsch")` — **in the same
commit as the resx**. The registry is what `check-localization.ps1` scrapes to decide which
files must exist, so a row without its file is a red build by design.

Finally: `check-localization.ps1`, `gen-strings.ps1` (expect **no** diff — the accessor is
culture-agnostic), build, test.

Nothing else changes: no markup, no view models, no settings UI, no `.csproj`. The SDK
produces the satellite assembly on its own (~55 KB), and nothing in
`Directory.Build.targets` can filter it. If that turns out to be false, the abstraction
leaked and that is the bug to fix.

### Getting the row right

- **The culture must be neutral** (`pt`, not `pt-PT`). .NET's satellite fallback serves
  every region from a neutral file — `pt-BR` and `pt-PT` both resolve to `pt` — but never
  the other way round, so shipping a regional code strands everyone else on English.
- **`CultureInfo.GetCultureInfo` is not a validity check.** Given any well-formed code it
  *manufactures* a culture rather than throwing: `"zz"` succeeds, and so does `"ls"` typed
  for `"sl"`. `EveryRegisteredLanguage_IsAWellFormedNeutralCulture` asserts membership in
  `CultureInfo.GetCultures(CultureTypes.NeutralCultures)`, which is the question you
  actually mean.
- **The endonym is not `CultureInfo.NativeName`.** .NET returns `français`, `čeština`,
  `polski` lowercase, because those languages lowercase their own name in prose. As a list
  label this app capitalizes — it ships `Español`, not `español` — so most endonyms differ
  from `NativeName` by their first letter, deliberately.

### Briefing the translator

One translator per language, never several sharing the file: terminology splits along
whatever line you split the work on. Hand them
`plans/2026-09-17-twenty-five-ui-languages/brief.md` (the do-not-translate register and the
core glossary) and require `glossary-<culture>.md` back, written **before** the
translation, fixing the term for each core concept, the formality register and the
quotation convention. That file is what makes the next string in that language consistent
with the last 389.

**A translator has an output-token ceiling, and 389 values in one reply can exceed it.**
Finnish did, and the agent died before writing a single byte. Slice the *brief*, not the
work:

```bash
foreach ($p in 1..4) { pwsh scripts/export-translation-brief.ps1 -Culture fi -Part $p -Of 4 -Out $SCRATCH/fi.brief.part$p.json }
# same translator, four output files, glossary fixed up front
& .\scripts\import-translations.ps1 -Culture fi -In @("$s\fi.part1.json", …)
```

The importer merges several files and **refuses a key that appears in two of them** — that
means the slices overlapped and one translation would be discarded in silence. (Pass the
array with `& .\script.ps1`; invoking `pwsh script.ps1 -In "a","b"` flattens it into one
literal path.)

### Then look at it

`LocalizedLayoutReviewTests` renders every settings page in every shipped language. **Use
it; do not write a second one.**

```bash
PARLOTYPE_LAYOUT_REVIEW=1 dotnet test src/Parlotype.Desktop.Tests --filter LocalizedLayoutReviewTests
# 500 images under reports/localized-layout/<culture>/
```

It is gated behind that environment variable because rendering that many pages leaves their
view trees bound to the `Localizer` singleton, which destabilizes every culture-bound test
in an ordinary run. The gate is load-bearing, and it looks exactly like missing coverage to
anyone who has not read the class — ADR-069 phase 9 opened by writing an ungated duplicate
and broke eight tests in precisely the documented way. If you want a narrower render, filter
inside that class.

Read the images. Fix clipping by making controls content-sized, **never** by shortening the
translation.

Aim that pass with `pwsh scripts/check-localization.ps1 -Report`, not with received wisdom
about which languages are long. Measured across twelve: `da` 1.08, `sv` 1.12, `ru` 1.15,
`pl` 1.17, `fi` 1.17, `nl` 1.18, `uk` 1.18, `pt` 1.21, `it` 1.22, `de` 1.23, `es` 1.24,
**`fr` 1.30**. French is the worst case and Finnish is mid-pack — the opposite of the
standard guidance, because German's `du` register and Finnish compounding both *cut*
length. Worst single strings run ~3× and are always short labels, never paragraphs.

## Hardcoded copy in AXAML — the migration is over

`scripts/localization-baseline.json` used to track how much hardcoded copy each `.axaml`
still had, while ADR-064's extraction was in flight. **That list is now empty.** Every
`.axaml` is clean, so a literal you add fails the check outright — there is no allowance
left to spend.

`-UpdateBaseline` exists only to record progress and cannot raise a count. If you find
yourself reaching for it, the answer is almost always to move the copy into resx instead.
The one legitimate use is when the scanner's own attribute list got wider and is now seeing
copy it used to miss, which needs `-Rescan` as well — deliberately a separate switch, so
the diff shows the scanner change and the count increase landing together.

`allowedValues` holds the handful of strings that are not copy at all (`Parlotype`, the
`sk-…` / `xai-…` key hints).

## Before you finish

```bash
pwsh scripts/gen-strings.ps1
pwsh scripts/check-localization.ps1
dotnet build Parlotype.slnx
dotnet test src/Parlotype.Desktop.Tests
```

If the build fails with a file lock from `.NET Host` / `testhost`, a previous test run is
still holding the output. Kill it by PID and rebuild — this is frequent enough here that it
is worth checking before doubting the change itself.

Then the part the tools cannot do: **switch the language in the running app and look at the
page you touched.** Every live-switch bug in this codebase was found that way and none was
found by a check.
