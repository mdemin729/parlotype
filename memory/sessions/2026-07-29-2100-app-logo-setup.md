# Session: 2026-07-29

## Active Focus
- [Assets/parlotype.ico](../../src/Parlotype.Desktop/Assets/parlotype.ico) — replaced the placeholder gray-circle "P" icon with the Parlotype waveform mark (from user-supplied `parlotype-mark.svg`), rendered in brand blue `#378ADD`, multi-resolution (16/32/48/64/128/256px).
- [Parlotype.Desktop.csproj](../../src/Parlotype.Desktop/Parlotype.Desktop.csproj) — added `<ApplicationIcon>Assets\parlotype.ico</ApplicationIcon>`, which was previously missing entirely (window/taskbar icon was falling back to the default .NET icon; only the tray icon in `App.axaml` referenced the ico file).
- Iterated once on user feedback: the glyph read as too small at tray/taskbar sizes, so re-rendered with the mark scaled to ~92% fill of the icon canvas (up from ~55%), the practical max before the rounded bar ends start clipping at the frame edge.

## Decisions Made
- Used the SVG's raw shape bounding box (x:10–110, y:10–80 within the nominal 120×90 viewBox) rather than the full viewBox for sizing math — the original viewBox already had ~8–11% padding baked in, which is why the first pass looked smaller than intended even at "66% of canvas".
- Final `.ico` packed with Python/Pillow, not ImageMagick, despite the user installing ImageMagick for this task — `magick` stored the 256px frame as an uncompressed bitmap (370KB ico vs. 12KB with Pillow's PNG-compressed frames). Used Inkscape for SVG→PNG rasterization either way (better anti-aliasing for rounded rects than ImageMagick's rsvg delegate in a quick comparison).
- No ADR — asset swap + one csproj property, doesn't touch Core/DI/dependencies/subsystems.

## Facts Learned
- This worktree's `Parlotype.Desktop.csproj` had no `ApplicationIcon` set before this session — the exe's embedded icon (which drives Windows taskbar/title-bar icon when `Window.Icon` isn't set) was the default .NET icon, not `parlotype.ico`. Only the tray icon was wired up.
- Environment now has Inkscape 1.4.4 (`C:\Program Files\Inkscape\bin\inkscape.exe`) and ImageMagick 7.1.2-Q16-HDRI (`C:\Program Files\ImageMagick-7.1.2-Q16-HDRI\magick.exe`) available, but a freshly-run `winget install` doesn't update `PATH` for already-open shells — had to call `magick.exe` by full path in the same session it was installed.
- `System.Drawing.Icon.ExtractAssociatedIcon(exePath)` in PowerShell is a fast way to visually verify an embedded exe icon changed, without needing to launch the GUI (useful for this tray-only app where there's no reliable main window to screenshot).
