## Decisions Made

- **Live language switching, no restart** — and it needed **no `{ReflectionBinding}`
  exemption**, which the plan had priced in as its cost. Avalonia 12 renamed `Binding` to
  `ReflectionBinding` and added `CompiledBinding.Create<TIn,TOut>(expr, source)`; giving each
  key its own `LocalizedString` makes the expression a plain property access, so `{loc:Tr}`
  is a compiled binding.
- **`Strings.cs` is generated** by `scripts/gen-strings.ps1` and checked in, superseding
  ADR-056's hand-written accessor. `{0}` keys also get `Format_<key>(...)` so wrong arity is
  a compile error.
- **`CurrentUICulture` moves, `CurrentCulture` does not** — dates and numbers keep following
  Windows regional settings, because the interface language is not a claim about location.
- **Display copy leaves Core**: `WaitTimeOptionExtensions.GetDisplayName` → Desktop;
  `GetSeconds` stayed. Model catalogs keep English names (identifiers, not prose).
- **RU/ES ship now**, covering all 45 existing keys, rather than waiting for Phases 4/5. Keeps
  "every key exists in every locale" true from the start instead of retrofitting it onto a
  stale corpus.
- Language rows are **endonyms, never translated**; only "System default" is localized.

## Facts Learned

- `JsonFileStore` awaits without `ConfigureAwait(false)`, so blocking on `ISettingsService`
  from Avalonia's UI thread **deadlocks before the first window**. Found while wiring startup;
  fix is `Task.Run` for the read, then apply the culture on the UI thread. Captured in
  [[../knowledge/sync-over-async-deadlocks-app-startup]].
- The regression test for that only works if **settings.json actually exists** — with no file
  the read never suspends and the buggy form passes. Verified the test hangs the test host
  when the fix is undone.
- An `[AvaloniaFact]` **does** carry an `AvaloniaSynchronizationContext` (probed directly), so
  it is a faithful stand-in for the real UI thread.
- The `// <auto-generated>` header opts a file out of the project's implicit nullable context,
  making `object?` a **CS8669 error** under warnings-as-errors — generated code needs an
  explicit `#nullable enable`. This is exactly the hazard ADR-056 cited when it avoided
  designer generation.
- Avalonia 12 has no `Avalonia.Data.Binding` type at all; it is `ReflectionBinding` +
  `CompiledBinding`, and `IBinding`/`InstancedBinding` are gone in favour of `BindingBase`.

## Phase 2 notes

- Guardrails are enforced **twice**: the PowerShell script (fast, precise, what the hooks
  call) and `LocalizationParityTests` (so `dotnet test` and `release.yml`'s gate enforce it —
  a hook only covers sessions that go through Claude). Both read the same
  `localization-baseline.json`, so the piece most likely to drift cannot.
- No separate CI workflow was added: the repo has none, only `release.yml` with a
  `dotnet test --no-restore` gate, which now covers all three checks.
- The literal baseline is **shrink-only**, and a file that reaches zero must leave the list.
  That last rule is what stops the baseline going stale as phase 3 progresses.
- Every failure mode was verified by injecting it: missing key, dropped placeholder, a
  language registered without a resx, a new literal in a migrated file, a verbatim-English
  translation, and both hook events. The guard exits 0 on its own internal failures so it can
  never wedge a session.

## Phase 3a notes

- 38 keys; AXAML literals 183 → 171, files 22 → 19.
- **The hook fired on my own work** and correctly flagged three files dropping to zero with
  a stale baseline. Its lead line said "left the translations out of step", which is wrong
  when the tree strictly improved — the guard now distinguishes progress from regression,
  since 3b–3d will hit that case constantly.
- Added a fourth check after finding the risk mid-batch: **`{loc:Tr}` keys must exist**. A
  typo compiles, does not throw, and renders the raw key name. Verified it fails on an
  injected typo in both the script and the test.
- Fixed a false positive in both scanners: XML numeric character references (`&#x2715;`)
  contain the letter `x`, so glyphs were counted as translatable copy. That alone removed
  `OnboardingWindow.axaml` from the baseline entirely.
- Hit the heredoc backslash-stripping trap **again** (the PowerShell `-replace` pattern
  came out as `'\'` instead of `'\\'`), despite having recorded it. Use the Write tool for backslash-heavy content — and note it eats non-ASCII too, which bit twice more later.

## Phase 3b notes

- 97 keys; AXAML literals 183 → 132, files 19 → 11. Resx is now 180 keys x 3 languages.
- **All 16 remaining section titles and all 5 category headers went in this batch**, not
  just 3b's own pages — a half-translated nav pane reads worse than a translated nav over
  an untranslated page body, and the titles are cheap.
- The Runtime "restart required" note was five `<Run>`s with two bound runtime names
  interleaved. Word order is frozen by that markup, so it is untranslatable by
  construction; collapsed to one composite format on a new `RestartRequiredNote`. Cost: the
  bold on the two names. Recorded the rule in the skill — 3c/3d will hit it again.
- **Both scanners were blind to `OnContent`/`OffContent`** (12 literals). `\b(Content)`
  does not match inside `OnContent` — the letter before it is a word character, so there
  is no boundary — and each attribute therefore needs its own alternative. Widening
  the list legitimately *raises* baseline counts, which the shrink-only rule forbids — hence
  a separate `-Rescan` switch, documented as "only when the attribute list changed", so the
  scanner diff and the count increase land in one reviewable commit.
- Extracted `SettingsWindowViewModelFactory` from `SettingsWindowViewModelTests` so the
  localization tests can build the whole shell without duplicating 25 lines of wiring.
- The guard's new progress wording got its first real outing and read correctly.

## Phases 4-5 notes — the layout review found two real defects

Rendered all 19 settings pages in en/ru/es via a new `LocalizedLayoutReviewTests`
(`reports/localized-layout/<culture>/`) and actually read the Russian images.

- **Layout: nothing clipped.** Russian runs ~35 % longer and every page just reflowed —
  the settings markup is wrapping `StackPanel`s with no fixed label widths. Worth knowing
  it is a property of the markup, not luck.
- **The check had a blind spot: element *content*.** `<TextBlock>some words</TextBlock>`
  is not an attribute, so the literal scan never saw it. Two whole paragraphs — the Cloud
  providers intro and the Gemma 4 engine note — sat untranslated while the check reported
  "0 literals". Caught only by looking at a screenshot. Both scanners now check element
  content too, verified against an injected case.
- **A real threading bug of mine, and a flaky-test hunt.** `Localizer.SetCulture` raised
  `CultureChanged` on the caller's thread; subscribers rebuild `ObservableCollection`s and
  notify bindings — UI-affine work. It surfaced as 13 failures that appeared only under a
  full solution run and **passed on re-run**, because whether a notification reaches a live
  control depends on GC timing. Marshalling `SetCulture` through `Dispatcher.UIThread` was
  necessary but *not sufficient*; making every culture-changing test an `[AvaloniaFact]`
  (which is how the app actually calls it) is what made three consecutive solution runs
  clean. Captured in [[../knowledge/culture-changing-tests-need-avaloniafact]] along with
  two xUnit traps hit on the way: `[CollectionDefinition]` must sit on a marker class, and
  `SkipUnless` requires `Skip`.
- The layout review harness is now **opt-in** (`PARLOTYPE_LAYOUT_REVIEW=1`). It renders 19
  view trees that stay bound to the `Localizer` singleton, which is exactly the kind of
  residue that makes everything downstream timing-sensitive. A review tool is not worth an
  unreliable `dotnet test`.

## Phase 6 notes — hotkey display

- Localized the hotkey list, mode badges, Help lines and the tour's hotkey lines with a new
  `HotkeyText` in Desktop. **No Core change was needed**, and that turned out to be the
  right shape rather than a shortcut: Core's `HotkeyGesture.DisplayString` is written by the
  hotkey log lines, and a log that changes language with the UI cannot be grepped. So Core
  keeps the invariant form and Desktop owns the display one — exactly ADR-064's split.
- **Key names are never translated** ("Ctrl", "Space" — what is printed on the keyboard),
  but the words around them must be *formats*, not concatenation. Spanish puts the side
  after the key ("Ctrl derecho") where English puts it before ("Right Ctrl"). Caught a
  Russian case error the same way: the first render said «Удержание Правый Ctrl»
  (nominative) where the phrase wants genitive — now «Удержание правого Ctrl». Both
  consumers of that slot read "verb + side + key", so one genitive form serves both.
  That makes three findings from reading rendered screenshots that no test produced.

## Phase 6 notes - the messages Core builds

The remaining copy was not labels but **sentences**, assembled from things only Core knows:
which reserved shortcut a chord hit, which mode a binding already uses, why a base URL was
refused, what HTTP status a provider returned. Core has no resources and must not get any.

- **The reason travels as data; the words are chosen in Desktop.** Core gained
  `HotkeyConflictReason` + `ReservedShortcut`, and `CloudConfigurationError` +
  `CloudBaseUrlError` + a `CloudBaseUrlFailure` record; both cloud exceptions now carry the
  parts (engine, HTTP status, the provider's own parsed text) instead of only a finished
  sentence. `HotkeyText.Conflict` and a new `CloudErrorText` do the wording. The English in
  Core stays as the **invariant** form the logs write - the same split
  `HotkeyGesture.DisplayString` already had.
- **`CloudBaseUrlValidator` came along.** Its error fragment was user-facing too: the Cloud
  providers page shows it under the base-URL field. It now returns the failure as data.
- **Every `Cloud_*` format opens with the provider slot**, followed by a colon or a verb.
  Not incidental: the provider name is itself translated, and a mid-sentence slot would ask
  Russian to inflect a string it is handed verbatim. Pinned by a test rather than a comment,
  because it is a constraint on *future copy edits*, not on today's.
- **The provider's own error text is substituted, never translated.** It arrives already
  written, in whatever language the provider chose.

**The guardrail these enums need is a different shape.** The resx parity checks cannot see a
member added without its key: the key is absent from every language at once, so the
languages still agree with each other and every existing check passes. `LocalizationTests`
therefore loops each enum and asserts the *Russian* rendering contains Cyrillic - which
fails both for a missing key (the lookup returns the key name) and for a fallback to Core's
English. Verified by blanking one RU value: it fails naming `ReservedShortcut.GameBar`.
Worth noting the nearest existing check, `NoKeyIsAccidentallyUntranslated`, would not have
caught it either - it only looks at values longer than 25 characters.

**The layout review earned its keep a fourth time.** These sentences are only reachable
after an interaction, so the harness never rendered them; it now drives three hotkey
conflicts and a rejected base URL. Reading the Russian images immediately showed
«... в режиме «Вкл./выкл.».» - the badge abbreviation's period stacked against the
sentence's. Fixed by giving the in-sentence mode its own keys, spelled out in the genitive
(«переключения»), leaving the badge abbreviated. English wants the opposite split
(lowercase in the sentence, capitalized on the badge), which is the argument for two keys
rather than one reused.
