# Session: 2026-04-30 — Model Hot-Swap on Selection

## Decisions Made
- Added `UnloadAsync()` to `ISpeechRecognizer` rather than re-creating the singleton recognizer — simpler lifecycle, avoids factory/service-locator patterns. See ADR-017.
- Kept `SelectModelCommand` as synchronous `RelayCommand` (not `AsyncRelayCommand`) to avoid `CanExecute` flicker — async work (stop, unload, persist) runs via fire-and-forget.
- `UnloadAsync` guard: throws `ObjectDisposedException` if disposed, no-ops if not ready. `DisposeAsync` calls `UnloadAsync` before setting `_disposed`.
- Removed `RefreshCache()` from selection path — cache status doesn't change on model selection, only after download.

## Facts Learned
- CommunityToolkit.Mvvm `AsyncRelayCommand` (generated from `async Task` methods) sets `CanExecute = false` while running. If multiple buttons share the same command instance (like in an `ItemsControl`), ALL buttons disable/re-enable simultaneously, causing visible flicker.
- xUnit v3 analyzer rule `xUnit1051` requires `TestContext.Current.CancellationToken` for any method accepting `CancellationToken`.
